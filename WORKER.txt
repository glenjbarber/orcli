# WORKER.txt

What to hand a worker to start on the core pieces of the orcli interface
redesign. Copy and paste friendly. Supersedes `give2spawn.txt`, which carries a
superseded decision and says so below.

/spawn You are working in the orcli repository, in the worktree at
worktrees/feature/tui-redesign, on the branch feature/tui-redesign. Read
AGENTS.md first. It holds the operating rules and it is read by default. Then
read DESIGN.md, then the decision records under staged/, starting at
staged/adr-0000010-interface-api.txt and staged/adr-0000011-editing-keys-and-input-history.txt.

This is a ground-up redesign of the terminal interface. The frame currently in
internal/tui is being replaced and is not a constraint. Do not repair it and do
not port from it. Do not read tui-redesign.txt; it is written for the
superseded one-character, 20-row frame.

Do not merge. Commit on the branch and stop.

The unit to build is the core everything else sits on. Nothing else can be
built until these exist, so this unit is deliberately narrow.

================================================================
BUILD THESE FOUR THINGS
================================================================

1. The pane set.

   A session is a conversation and owns its messages, its transcript, its
   cursor, where the reader has scrolled, what /copy copies, what /permit
   allows, and its input history. A pane is an entry that points at one
   session.

   Pane 0 is the main session. It exists at startup and cannot be closed.

   A new pane takes the LOWEST AVAILABLE numeric ID. With 0, 1 and 2 open,
   close 1, open a pane, and the new pane is 1, not 3.

   Panes do not renumber. Close pane 2 of five and you have 0, 1, 3, 4. A
   number means the pane that was given it.

   The set holds which pane is focused, in one place, and everything that
   reads focus reads that one place.

   A pane ID is not a level. internal/tui/levels.go retires a level rather
   than returning it to a pool, and says why: a reader who copied level 3 an
   hour ago must not get whatever took the number. Pane IDs are reused and
   levels are not. A pane ID is for navigation, a level is for attribution.

   STOP AND ASK BEFORE BUILDING THIS. The lowest-available rule above is
   contradicted by section 9 of distributed-llm-system-scope-2026-10-05.txt,
   which says a new pane takes the next incrementing identity starting at 1,
   that closing a pane does not renumber the others, and that this supersedes
   the lowest-free rule. Do not resolve it yourself and do not build either
   rule. See OPEN below.

2. The message queue.

   One queue per session, first in first out.

   A message typed while the model is working is queued rather than sent.

   Escape sends the HEAD of the queue immediately, as an update to the
   request in flight, so tool calls already made and answered stay answered.

   A message sent by escape leaves the queue when the model has processed it,
   not when it is sent. A reader who presses escape twice must be able to tell
   whether the first press landed.

   When the turn settles, queued messages go one per turn. The first starts
   the next turn, that turn settles, and the next starts. Do NOT drain the
   queue in one pass. Three questions in one request cannot be attributed in
   the transcript, and the queue exists so a reader can see which answer
   answers which question.

   Where the queue lives is settled: in memory in the session, behind a small
   interface, with SQLite available later behind the same interface. A queued
   message is not durable before it is sent. Do not add the SQLite dependency
   yet; build against the interface. This is record 0000012.

3. The receive queue and the scroll position.

   Rows arriving from a running turn go into a queue IN THE SESSION, not into
   the painter. The painter drains it only when the reader is at the live edge.

   Nothing is dropped, only deferred. A reader who scrolls back through a long
   reply keeps reading while rows continue to arrive, and the rows land when
   the reader returns.

   Rows are folded at draw time and NEVER on arrival. A row cut to a width when
   it arrived would be cut again when drawn and would lose its tail twice.

   Scrolling is READ, not stored. Derive it from where the viewport is
   relative to the bottom. Do not keep a separate reading-mode variable; a
   second one could disagree with the view. A reader at the live edge is live,
   a reader away from it is reading, with nothing to reconcile.

   The live activity readout, which is the endpoint's progress reporting, is
   suppressed while the reader is scrolled away. It is a reading of the
   present and a reader reading history is not present. Show [scrollback] while
   it is suppressed. Both end when the viewport reaches the live edge.

   That distinction is the whole point: transcript rows are deferred and kept,
   live activity is not shown.

4. The line editor.

   A line editor over the prompt row, holding one line, with these keys:

   Ctrl+A  move the caret to the start of the line
   Ctrl+W  erase the word before the caret
   Ctrl+U  erase from the caret to the start of the line
   Up      walk the input history back one entry
   Down    walk the input history forward one entry

   Up and Down stop at each end. They do not wrap.

   The history is DEDUPLICATED. An entry that duplicates an earlier one is
   kept ONCE, at the position of its most recent occurrence, and the history
   is ordered MOST RECENT FIRST. Three presses of ls an hour apart give one
   ls, at the top, and the older ls is gone rather than three rows down.

   Deduplication is on the exact text of the line. Two lines differing only in
   trailing whitespace are two entries. Do not trim.

   Every line that was sent is remembered, whatever it was. A question, a
   command and a pasted paragraph are all history. A bare command word is
   remembered like any other line.

   A line that was queued is remembered when it was SENT, not when it was
   queued, so the history holds what the model was actually asked.

   Walking the history does not send anything and does not clear the line. Up
   replaces the field and leaves the caret at its end.

   The history is ONE HUNDRED entries, exact text, nothing shortened, the
   hundred most recent with the oldest falling off. The bound is on count and
   not on length, so a pasted paragraph is a full-length entry. /autocompact
   bounds it and is not built. This is record 0000015.

   The editor reads blocks rather than bytes, the way internal/tui/line.go
   does. A terminal writes a whole mouse report in one piece, so a byte-at-a-
   time read sees the opening escape alone and a lone escape is an interrupt.
   Hold a prefix too short to recognise until it is whole.

================================================================
NOT IN THIS UNIT
================================================================

The screen and its six regions. The status bars. The twiddle. The live
activity readout's phrase set. Copy and paste. Restore. Permissions. The
Ctrl+B prefix key and its command set. The in-terminal menu. The shell-line
no-op rule.

These are all decided in DESIGN.md and in the records under staged/. They are
not built here because each depends on the four things above.

The pane bar is back on the screen; its earlier withdrawal is reversed by
record 0000019. Seven regions remain: live window, scrollback indicator, mouse
indicator, status bar 1, status bar 2, prompt, pane bar. The shed order for
the other six is record 0000016, which explicitly left the pane bar's place in
that ladder unsettled; 0000019 reopens it as question 25 rather than guessing at
it, and it is not built here either.

OPEN, AND DO NOT INVENT AN ANSWER
================================================================

Where the queue is stored. Settled by 0000012, listed here so it is not redone.
Whether the prefix is escapable.
The clipboard path on macOS Terminal.app with Secure Keyboard Entry.
Whether copy is owned by the session or by the terminal.
The permissions database schema.

reader answering it later should not find it already decided in your code.

================================================================
ONE MORE THING
================================================================

A reader who types a shell command into the wrong window, so `ls` and enter
with no question asked, should get nothing. That rule exists and its
exception does not: what makes a line a shell line, and what "directly in
response to a question from the model" means, are both undecided. Do not build
it. Build the field so the rule can be added to it later without touching the
editor.

================================================================
WHAT SUPERSEDES THIS FILE
================================================================

give2spawn.txt is superseded by this one and differs in four places. Where they
differ, this file is current.

  The queue is settled rather than open. 0000012 decides it.

  The history is settled rather than open. 0000015 gives the count, the bound on
  length, and the treatment of a bare command word.

  The pane bar was gone from the screen when this file was written, leaving
  six regions rather than seven, and record 0000016 carried the shed order for
  them. Record 0000019 reverses that: the pane bar is back, so this is no longer
  a difference from give2spawn.txt on this point, if it ever was one.
  give2spawn.txt is not in this worktree to check against.

  The pane ID rule is contradicted by section 9 of the scope document, and
  this file tells the worker to stop rather than to pick one.

Two more facts a worker should have and give2spawn.txt does not carry.

  `internal/tui` has no SetScrollRegion. The frame writes terminal rows
  directly. Anything that sets a scroll region is new, and the scroll region
  is where a short terminal will be wrong first.

  `internal/tui/worker.go` already holds a worker as a value carrying a
  Level, and `registry.go` already reaches one only by a line the reader
  types. A worker cannot be woken, queried or steered from outside the
  process. The broker direction does not change that and a new path into a
  worker from outside would contradict what those files say about themselves.

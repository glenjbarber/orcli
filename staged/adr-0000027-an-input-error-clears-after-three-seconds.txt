# 0000027 An input error clears after three seconds

- Status: accepted, and SUPERCEDED by `UI-redesign.md`, which supersedes every prior UI architecture ADR
- Date: 2026-10-05
- Supersedes: nothing. It settles question 15 in `QUESTIONS.md`

## Context

Question 15 asked how long an input error stays in the input field before
clearing, already settled as clearing on a timeout rather than on the next
keystroke so a reader who looked away sees the field recover. The question
named its own answer as provisional before it was given: "the first value
will be wrong."

Nothing else in this design supplies a number to derive this from. The
thinking-word timer resets on an API update or seven seconds, whichever is
shorter, but that duration is tied to the API's own cadence and an input
error has no comparable external event to peg to.

## Decision

**An input error clears three seconds after it is shown.**

## Reasoning

No derivation. Three seconds is a conventional length for a short transient
message, long enough to read once and short enough not to sit in the way of
typing for long. The question's own framing is carried forward rather than
dropped: this value is expected to be wrong and revised once a reader has
actually watched it clear.

## Consequences

A reader who looks away for longer than three seconds does not see the error
at all when they look back. That is the same trade every timeout-based
transient message makes, named in the question before this record existed.

## Alternatives considered

None weighed. The question asked for a number with no claim that any
particular number was better reasoned than another, and this record does not
manufacture a comparison that was not made.

## What this leaves open

Whether three seconds is right. Named here as expected to be revised, not as
a question reopened; a future record that changes it does so because it was
watched and found wrong, not because this one was incomplete.

## Notes

Nothing in the tree has changed. There is no input field in the tree built
against this timeout.

Design records in this worktree, both committed before the code.

staged/design-input-loop.txt is the reader's specification, copied from
design-input-loop.md in the main worktree. That file is untracked and ignored and
lives only there, so it is committed here to travel with the code.

staged/status.txt is this worker's own record: the same unit read against the
code, the decisions taken where the specification left a choice, and the
alternatives rejected with their reasons.

What this unit is: raw mode, a bounded block reader, a key reader, a line editor
over the pinned prompt row, and a loop that hands every slash line to the
dispatcher and every other line to a turn. It is one unit because both halves
become true at once or the binary is less usable than one with neither.

What it does not do: /spawn, /delegate, /btw, /queue, /redirect,
[enter][enter], mouse reporting, tools, paste handling, and /copy and /close
wired to a keystroke. A turn carries the question and nothing else, which is left
open on purpose because what a turn carries has not been decided.

Unverified: how the stack looks on a real screen, whether the two-cell twiddle
reads as one figure, and whether an escape read as a key while a turn is running
reaches the loop. All three need a terminal.
